## Recipe components — current status and implementation plan

**Partially implemented.** In Add/Edit Recipe, the checkbox after the costing section reads “This recipe is a compound prep (yield unit must be a pantry unit, e.g. g).” Saving it creates a linked pantry ingredient with `compoundRecipeId`; that prep can then appear in the ordinary ingredient dropdown. There is no separate “Add recipe component” action, recipe search, finished-yield display or linked-source navigation in that row. It is not the requested complete sub-recipe workflow.

Existing cost rollup follows the linked source recipe and divides its recipe cost by **finished yield**, recursively. It rejects compound cycles. Source changes update current estimates; completed batches retain their cost snapshots. The label ingredient/allergen resolver expands linked preps into source ingredients, scaling by finished yield, and retains source ingredient provenance. An existing limitation is that some other simple allergen summaries read the prep's empty allergen array rather than this recursive provenance; the component work must unify those summaries.

**Current production distinction:** completing a prep batch consumes its raw ingredients and receives prepared stock. Completing its parent consumes that prepared pantry stock only. This path does not make the component during the parent run and does not deduct its underlying ingredients a second time. There is currently no explicit make-with-parent mode.

Proposed relationships: keep stable source recipe IDs and the existing tenant-scoped linked prep IDs; add explicit component-line metadata for source recipe, amount/unit, ingredient-specific conversion provenance and production mode. Enforce tenant references and cycle detection server-side, including transitive self-use. Map legacy prep ingredient lines to **use prepared stock** without changing saved quantities, ingredient IDs or history. Do not flatten copied ingredient lists into parent lines. Any normalized relational additions require a new forward migration with tenant keys and policies.

Proposed editor: leave every existing section and ingredient-entry behavior in place. Inside Ingredients, offer **Add ingredient** and **Add recipe component**. A compact component row searches existing recipes, shows the linked source's finished yield/unit, accepts the used amount/unit, shows proportional cost, and offers Open recipe. Source editing opens separately with unsaved-parent protection. Invalid/missing conversions show a precise error; no weight/volume guessing. Keep the source recipe linked rather than copying it.

Yield/cost rules: amount in source yield units ÷ positive finished yield × source recipe estimate. A verified conversion is required when usage and yield units differ; arbitrary “loaf”/“cake” units need explicit definitions rather than being assumed equivalent to each or weight. Count source ingredients/labor/overhead once inside its component estimate; parent labor represents only additional parent work. Source edits immediately affect parent estimates, with an “estimate follows source recipe” note, but never completed-batch usage/costs. Never separately add expanded source costs to the already costed component line.

Production plan: **Use prepared stock** consumes only the linked prep lot and its actual valuation. **Make with this run** creates an explicit linked child production operation with planned/actual finished yield, usage and labor, and transfers its actual consumed component cost into the parent. The parent cannot additionally deduct that component's raw ingredients or count child labor twice. Reserve/complete the child and parent atomically where possible, or require an explicit reconciled child completion before parent completion. Block insufficient prepared stock; do not silently switch modes. Saving/editing a recipe never posts stock.

Phases: (1) approved prepared-stock component editor, tenant/cycle/conversion validation and provenance; (2) explicit child-production planning/completion with actual costs and audit reconciliation; (3) compatibility review of existing prep lines and ambiguous yield units. Do not expose make-with-parent as working before phase 2. Tests cover partial finished-yield use, standard/verified/missing conversions, nested/direct cycles, transitive allergens/statements, source edits versus historical snapshots, single-counted labor/overhead, prepared-stock consumption, child-production failure/retry and tenant isolation. Approval of the phased plan is required before coding this feature.
