# Shared popup positioning audit

## Production baseline and cause

On 2026-11-13, Netlify's live published deployment was `6af70340e57a94221733e7d3`, commit `21ca53d2cbb2fc18cfe44609febeac70763c35a5`, published at 12:33:07.003Z. Production `/oven` served `oven-DLA_-OGN.js`, `label-studio-BayNchEE.js`, and `index-DwXFf116.css`. The ingredient-specific `positioning: css` opt-out and saved-unit editor safeguards were already present. Thus the previously prepared ingredient-specific correction had reached production; the shared modal correction in this change had not.

A production Chromium check with synthetic workspace responses reproduced the batch dialog at x=-171px on a 390×844 viewport, before attempting any save. The shared component still supplied `translate-x-[-50%] translate-y-[-50%]`, top/left centering utilities, and zoom animations. Production CSS contained individual `translate` utility declarations, but the mobile rule had been lowered to `transform:translate(0,0)!important` with no separate `translate:none`. An identity transform does not cancel an independent translate property. This is a compiled CSS interaction, not an ingredient-specific offset or a positioned workspace ancestor.

The shared `DialogContent` now omits centering and zoom utilities altogether. A scoped desktop-only selector centers the generic modal using a single transform; mobile retains the existing visual-viewport and safe-area anchor. The viewport listener, portal to body, Radix modal scroll lock, focus restoration, existing scroll containers, layouts, and all draft state remain intact. No global transform reset or per-dialog offsets were added. The overlay's opacity animation remains; content has no final animation transform to override position.
