## Restocking data and interface

`ItemRestocking` supplied plain labels and a compact two-column group in Add Item and the existing item editors. Item code, Barcode, Where it's stored, Notes and the collapsed Where to buy & item details retained their existing underlying keys. Reorder levels remained stock-unit quantities; purchase minimums used purchase units and displayed recorded package contents. A threshold became low stock at equality under the existing status rules. Existing out-of-stock status retained priority. Add Item's existing blank-to-zero default was explained; existing Edit Item blank-review behavior was preserved. Valid stock-unit changes converted alert amounts, unverified conversions required review, and separate Add Item type drafts did not reinterpret an entered alert quantity across item types.

No supplier-specific minimum structure existed. Optional `minimumOrderQuantity` and its `minimumOrderUnit` basis were stored in the existing tenant-owned Netlify Database JSON records, with no new relational schema or migration. Server validation accepted positive quantities, enforced whole count packages, converted verified purchase-unit changes and required review for unverified ones. Existing minimums stayed blank. Add, ordinary ingredient update, fabric, material and resale handlers preserved the field. Minimums did not enter pricing, stock, order creation or receipt restrictions. Cancel and tab switching retained their established draft semantics.
