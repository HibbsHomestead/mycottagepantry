# Product modal verification

The food product dialog previously used the generic `.app-dialog` outer `overflow-y: auto` with an unconstrained form, desktop grid rules based on browser width, and a sticky footer offset by `bottom: -28px`. This made the whole editor scroll and allowed the footer to overlap the final fields. The packaging markup had six controls inside a four-column grid; calculation-box direct-child flex styling also overrode its grid display. Mobile button wrapping then exposed the compressed Remove action as stacked text.

The product dialog now opts into a bounded flex shell, with a non-scrolling header/footer and one shrinkable middle scroll region. Existing shared dialog visual-viewport tracking and safe-area support remain in use. Tabs stick within the middle region through its full scroll range. The summary moves below the form before its usable width becomes too small. Packaging rows explicitly restore grid layout, respond to their containing column width and reserve a 44px action column. The existing Lucide Trash2 icon and shared ActionTip tooltip replace Remove; it still filters only the product draft array.

Changed UI components: WorkspaceApp, new ProductFormBody, PackagingEditor, and product-editor.css. The shared Radix dialog implementation was inspected and left unchanged. Other generic forms receive a fragment from ProductFormBody and retain their original DOM. Calculations, taxes, categories, inventory records, migrations and existing close/unsaved-change handlers were unchanged.

Chromium used synthetic demo responses at http://localhost:8889/capture-fixture with the real React app and CSS, through Netlify dev. Create Product and Edit Product were exercised at 1440×900, 1280×600 and 390×650. Six packaging rows were added, then first, middle and last rows removed. Checks covered long item names, the 44px buttons, keyboard-focus tooltips, nonoverlap with Required, all three tabs, tab state, keyboard focus staying inside the dialog, wheel scroll lock, viewport bounds, absence of outer vertical/inner horizontal overflow, footer access at top and bottom, Cancel, Escape and scroll-lock restoration. Mocked network capture confirmed these interaction checks sent no save/inventory mutations. Existing component tests also checked draft preservation, save payloads and validation across tabs. No real business data was used.
