## Receipt findings and changes

The earlier defect had been upload-only storage followed by a blank draft: upload had not invoked the extraction operation, and that operation had shared a broader disabled AI gate. The existing repair now invoked the separately controlled receipt reader after upload. This run traced that implementation rather than treating successful storage as extraction.

Read-only inspection found the owner’s CCCC Sertoma PDF already posted manually. Its private original remained accessible. PDF.js found usable text on its single page. Real processing through the existing Google Gemini / Netlify AI Gateway dependency recovered vendor **CCCC Sertoma**, invoice **001993**, issue date **2026-07-26**, **Ozark Market Days Vendor 10x10 Booth Space**, printed quantity **1**, explicit unit price **25**, line total **25**, subtotal **25**, and total **25**. Tax and currency remained unknown. The existing posted receipt and associated accounting were not changed.

Further real-provider checks exposed intermittent invalid responses and timeouts. In particular, a provider could wrap a single receipt in a JSON list. The reader now accepted one unambiguous wrapped draft and rejected empty or multiple-draft results instead of taking only the first. It also retained valid receipt values for partial review when confidence or highlight-position metadata was malformed, removed only that unusable auxiliary metadata, and added explicit review warnings. Business fields remained strictly validated. Invalid-field errors identified safe field names without exposing provider request details. Truncated responses were detected before JSON parsing; missing default credentials received a configuration-specific message.

PDF.js continued to inspect every page. Text-only documents used embedded text; image-only and mixed documents sent the original PDF and available text to the existing Gemini document reader for OCR. Page coverage, unreadable pages, invalid results and partial extraction were explicit. Unknown values remained blank, printed package counts stayed separate from received stock quantities, and no package weight, conversion, tax rate or tax classification was inferred.

The existing editable review included vendor, date, receipt number, currency, descriptions, printed quantities/units, explicit unit prices, line totals/discounts, subtotal, tax, fees/shipping and grand total. It distinguished reviewed fields and calculated reconciliation. Ingredient/packaging suggestions required owner selection; existing creation forms, expense decisions and exclusion remained available. Retry preserved corrections and required an explicit choice before replacement. Reading did not post stock, update costs, create expenses, vendors or items. Confirmation retained server-authoritative posting and duplicate protections.

Originals stayed in private Netlify Blobs behind the authenticated workspace endpoint. Drafts and attempt history stayed in Netlify Database, scoped by verified workspace membership and row policies. The existing provider disclosure remained in the upload flow. Google received receipt text and, for scanned/mixed PDFs, the original file. No new external provider or credential service was introduced. This previously approved processing remained metered through Netlify AI Gateway; costs depended on document/model usage and account billing, with no fixed per-receipt price or monetary cap. Existing limits remained 4 MiB, 20 PDF pages, 120,000 embedded-text characters, 45 seconds per provider request, 12,000 output tokens, 10 attempts per workspace and 3 per receipt per UTC day. These limited calls, not a guaranteed dollar spend. OCR ambiguity and intermittent provider timeouts remained human-review/retry limitations.

## Built-in template deletion

Built-in starters were code-defined designs, while saved labels were independent editable snapshots. Template management gained a visible Delete action for starters as well as saved designs. Confirmation showed the exact name, explained workspace-only removal, and stated that saved labels, products, artwork and print history were preserved. Cancel made no request.

The server resolved built-in IDs against its own registry and persisted removal markers in the existing tenant-scoped template table. It did not delete the shared system definitions. Existing role, subscription and workspace checks continued to apply; stale saves could not restore a removed system ID. The library and starter picker filtered the persistent markers, so normal initialization, refresh, another signed-in workspace member and another device did not re-add the starter. No automatic restore action was added. Existing owner-template deletion remained intact, and source-template references on saved labels remained usable after removal. No schema or applied migration changed.
