Inventory count session responsive verification

The real Inventory → Ingredients → Inventory count sessions action was opened using the real WorkspaceApp and Radix dialogs with intercepted, disposable workspace records. No real inventory was read or changed.

The unmodified CSS failed the new browser regression at 320 × 568: the empty dialog's scroll width exceeded its client width by 28 pixels. The shell inherited an implicit grid track with an automatic minimum, while long action labels could force children wider than the available content width. The current source's empty 390-pixel popup already measured x=12, width=366; the exact reported left-side displacement was not reproduced. Its portal was a direct child of body, so a transformed application ancestor was not the observed cause. Existing mobile CSS supplied a translateX(-50%) transform and disabled Tailwind's separate translate property. Two different viewport-positioning rule sets also targeted this shell. The patch removed the obsolete count-shell rule and replaced mobile centering with explicit safe-area-aware insets. It did not claim that the screenshot's exact displacement was conclusively diagnosed.

The targeted CSS constrained the grid track and children, wrapped text and buttons, stacked narrow-screen footer actions, reserved heading space for Close, and capped the single dialog scroll region against the existing visualViewport measurements. Mobile size/position transitions were disabled after the keyboard simulation demonstrated delayed resizing. Radix's modal overlay, focus handling and scroll lock were retained; close released the lock. The desktop 900-pixel cap, count state, server behavior and mobile navigation rules were preserved.

Eight Chromium browser cases passed: 320×568, 375×667, 390×844, 430×932, 844×390, 820×1180, 1180×820 and 1440×1000. They covered the entry popup, saved-session selection, quantity entry, failed start/retry message, review confirmation, close/reopen quantity retention, scanner, unknown-barcode assignment selection, dialog bounds, absence of horizontal overflow, and scroll-lock release/reacquisition. The mobile cases additionally simulated a 300-pixel visual viewport with a 20-pixel vertical offset and checked the height cap. This was viewport API simulation, not a physical keyboard test. The unknown assignment was selected without saving or changing inventory.

Three existing rapid-count browser workflows also passed at 390, 820 and 1440 pixels, exercising start, scanning, package assignment, persisted resume, review, application and report/CSV using disposable intercepted data and the existing command processor. Eleven tests in inventory-counts, barcode-scanner and inventory-barcode-review component suites passed. Targeted ESLint, TypeScript and git diff whitespace checks passed. No build command was run.
