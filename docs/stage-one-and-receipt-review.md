**Receipt root cause and repaired workflow**

The upload path stored a private attachment and blank draft, but the frontend did not call the retained extraction operation. That operation was also disabled by the broader deferred-AI release gate. A production probe confirmed that the old operation was unavailable; successful upload did not demonstrate extraction. The actual saved CCCC Sertoma invoice contained usable text, so missing OCR was not the cause for that file.

Upload now saves the original and invokes a separately controlled receipt reader. PDF.js reads every page's embedded text and checks for image content. Text-only PDFs send extracted text to Google Gemini through Netlify AI Gateway; scanned and mixed PDFs send the original document together with available embedded text. Image receipts use the existing document reader. The supported retained model is `gemini-3-flash-preview`; this is Gemini document OCR, not a new Google Cloud Vision or Document AI integration. The server checks returned page coverage, validates the extraction schema, rejects truncated output, and flags unreadable/unverified pages for review.

The review form includes vendor, issue/purchase date, receipt number, printed currency, lines, printed purchase quantities/units, explicit unit prices, line totals/discounts, subtotal, tax, shipping/fees, total, and explained rounding adjustments. Unknown values stay blank. Printed and owner-corrected header values have provenance labels. Calculated reconciliation differences appear separately. Printed package counts never populate actual received stock quantities. Inventory lines require an item match and confirmed received quantity/unit; owner-reviewed name suggestions do not silently create or match records. Existing ingredient and packaging forms are available without leaving the receipt review. Other expenses and noninventory decisions retain their existing posting rules.

Reading alone creates no inventory movements, expenses, vendors, or items. Confirmation uses the existing server-authoritative posting and weighted-cost transactions. Original-file hashes reject duplicate uploads within a workspace, existing duplicate checks prevent duplicate posting, and confirmed receipts reopen with their evidence and related records. Retry first saves corrections, then offers explicit apply/keep choices for replacement values. Uploading, reading, ready, partial, and failed states are distinct. Failure preserves the saved attachment and entries and provides retry/manual entry; provider diagnostics are sanitized.

Files remain in private Netlify Blobs, accessed only through the workspace API. Extracted drafts and attempt history remain in Netlify Database under existing tenant policies. The server rechecks the signed-in identity and active write membership after the provider wait before applying results. Provider latency does not hold the workspace stock/accounting lock.

**Actual owner receipt and processing limits**

A read-only audit of the original **001993 CCCC Sertoma $25** recovered vendor **CCCC Sertoma**, invoice **001993**, issue date **2026-07-26**, the **Ozark Market Days Vendor 10x10 Booth Space** line, printed quantity **1**, explicit unit price **25**, line total **25**, subtotal **25**, and paid total **25**. Its single page had usable embedded text and was reviewed. Tax and currency remained unknown: no printed tax value was inferred, and a bare dollar sign was treated as ambiguous. Actual received inventory quantity remained blank. The existing owner receipt was already posted manually; it was not re-extracted into that record, reposted, or changed. Customer stock and accounting records were not changed during verification.

Google receives receipt text, and receives the original for scanned/mixed documents. This external processing was approved by the owner and is disclosed in the upload interface. Usage is metered through Netlify AI Gateway; charges vary by model/token usage and appear in Netlify billing. There is no fixed monetary spending cap. Durable limits bound reading to **10 attempts per workspace per UTC day**, **3 per receipt per UTC day**, **4 MiB per file**, **20 PDF pages**, **120,000 embedded-text characters**, a **45-second provider request timeout**, and **12,000 output tokens**. Attempts retain available token counts. The file limit accommodates Netlify's buffered request payload. Large, password-protected, damaged, or unreadable documents retain a manual path. These limits bound calls, not a guaranteed dollar amount. Image quality and model interpretation still require human review.
