# Reusable label templates and saved-label management

Label Studio now keeps reusable templates separate from saved labels using the existing editable-document records and database workflow. Existing saved designs remain labels. No data conversion, new service, schema migration, or manual master JSON save is required.

The editor offers **Save as New Template** with a name dialog. Complete designs retain dimensions and orientation, every element and element ID, positions, groups, visibility and locking, fonts and rich text, colors, images, and dynamic field bindings. Each template receives its own stable unique ID. Duplicate names are compared without case or surrounding whitespace, with Unicode normalization; the dialog offers a different name or an explicit update of the matching template. The server independently enforces duplicate prevention, revision checks, record type separation, and workspace ownership.

Opening a saved template restores the editable document. Changes require **Update Template**; existing label autosave continues through its established workflow. **Save as New Template** creates a variation. A label can also explicitly update a chosen existing template. Success is shown only after the server confirms the complete design and save reference. Retrying a lost save response uses the same operation reference and document ID. Unsaved edits retain recovery export/checkpoints and navigation/unload warnings.

The Templates section includes saved names and rendered design previews, search and style filtering, open, assign to products, rename, duplicate, and delete. Starting blank or copying a built-in starter creates a reusable template. Assignments, previews, and printing never create individual label records. A template can be assigned to several products; each resolves its current data independently. Edits show the assigned-product count and affect future output for those products. Deletion is blocked until assignments are resolved. Legacy saved labels and their existing assignments remain available without automatic conversion.

Templates support Single label or Front + Back labels. A set stores its Front design in the existing document and its independent Back layout in the same document's optional `back` property. Both have separate dimensions, typography, content and artwork. Duplicate as Front + Back set preserves the original Front and begins with an empty Back; blank sides block complete-set printing. Product assignment is optional in Images & Labels. Product display-name fallback and generated ounce/gram net-weight text are resolved without changing stored product values.

No schema migration or bulk conversion was performed. The available preview database did not contain the persistent owner's workspace, so counts of product-specific overrides and multiple-format legacy relationships remain unknown. Such records require inventory and review before conversion; visually different designs must not be merged. Legacy records, revisions, recovery checkpoints and print snapshots are retained. Rollback must retain a set-aware reader for newly saved paired documents; older code could otherwise output only Front.

My Labels includes a Delete action per label, selection checkboxes, Select All for filtered results, a selected count, and Delete Selected. Confirmation names a single design or gives the bulk count, with Cancel. Errors retain the records and selection for retry. Successful deletion updates counts and clears selection. Deleting the open design explicitly closes its editor, after the confirmation discloses that any unsaved edits will be discarded.

Deletion is an atomic, workspace-scoped soft deletion in the existing records. A revisioned deletion marker prevents a delayed save/list response from restoring a deleted design. The API rejects updates, print/export requests, and new recovery checkpoints targeting deleted designs. Existing checkpoints for the deleted design are resolved. Version history, print records, normalized elements, shared images/fonts, unrelated labels, and source templates remain intact. Creating a deliberately new editable recovery copy remains available.
