# Stock shelf weight units

The reported setup was reproduced with a synthetic jar priced at $6.98, a shelf unit of US cup, 0.375 cups per jar and a recipe unit of oz (weight). The oz option was present, enabled and available across unit families. The selection handler attempted to convert the reorder threshold and reorder quantity from the previous shelf unit before updating the selected unit. Even zero amounts required a conversion path, so a missing cup-to-ounce conversion aborted the handler and left US cup selected. This was not a render effect or an import resetting the selector. The editor initializes its draft when the ingredient ID changes; import mapping does not assign the shelf unit.

The selector now accepts oz (weight) directly. Zero reorder settings remain zero; positive amounts without a verified conversion become blank and require re-entry. Package contents are converted only through verified relationships. Otherwise the contents field is cleared, with an explanation asking for the verified net weight per jar. An imported weight is not treated as a verified conversion. The purchasing package remains jar and the recipe unit remains independently editable.

The workflow remains Inventory → Ingredients → View details → Edit Ingredient → Details & Costing. For an item with zero stock and no stock history, changing to an incompatible inventory basis requires entering verified package contents and explicitly confirming the new basis before Save changes. The old package relationship is removed from the active conversion graph so it cannot silently manufacture a weight-to-volume equivalence. The previous purchase basis is retained in the existing reference history mechanism. Unit costs are recalculated for the new basis; no stock is posted. A new basis and opening stock must be saved separately to prevent an opening count from being interpreted in the previous unit.

For an item with stock or history, the editor explains the restriction and exposes Review stock-unit conversion. Unit Conversions accepts an explicit measured relationship, its source/measurement notes and verification. Saving that relationship changes the shelf presentation while retaining the canonical stock unit, quantity, weighted-average valuation and historical records. If a trustworthy relationship is unavailable, the UI directs the user to preserve the existing item and create a separate weight-tracked ingredient. No automatic stock transfer or historical migration was added. The server checks the tenant’s own ledger, count and batch records rather than trusting a client claim that history is empty.

The browser fixtures used a confirmed 3 oz package and a separately measured conversion solely to exercise the workflow. These numbers are not a claim about the user’s product. TypeScript, formatting and whitespace checks passed. New files passed ESLint; baseline comparison found no additional lint findings in the existing files.
