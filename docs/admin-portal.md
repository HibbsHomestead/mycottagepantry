# Administrator access

Cottage Pantry Admin uses email and password through Netlify Identity, followed by an enabled server-side platform administrator grant. Customer membership and browser role flags never grant administrator access. Administration is restricted to its configured hostname; opaque sessions use host-only HttpOnly Secure cookies, expire after 30 minutes, and are checked against current Identity status, grant, epoch, origin and request headers on every request.

Sensitive actions require recent server verification, valid for ten minutes. Open **Verify existing admin authentication for sensitive actions**, then **Check verification methods**. If an authenticator is enrolled, enter its current code or a single-use recovery code. Otherwise, confirm the current account password. Successful verification rotates the session and reloads the page, clearing unsaved inputs. Password confirmation is recorded separately from multi-factor verification. An enrolled authenticator cannot be bypassed by choosing the password fallback.

To transition an account whose only second factor was a passkey, sign in with its password and confirm the password in the sensitive-action panel. No old device or enrollment deadline is required. To add an authenticator, open **Admin sign-in security**, choose **Set up authenticator app**, and confirm the first code from that app. Save the single-use recovery codes privately when displayed. Enrollment revokes other administrator sessions. Removal and recovery-code replacement require recent verification with an enrolled code. Secrets and recovery codes are never included in audit metadata.

If the password is unavailable, use **Reset password** on the sign-in screen. Follow the Identity email, choose a password, then sign in and confirm it. Password recovery does not grant administrator access, reset an enrolled authenticator, or issue an already verified administrator session. If an existing authenticator and all recovery codes are lost, the platform owner must verify the account holder through the established audited recovery process; changing a browser flag or resetting the password cannot remove that factor.

Authenticator encryption configuration is required only for authenticator setup and verification. It is independent of Stripe encryption. Missing authenticator setup configuration does not prevent password login or password confirmation for accounts without an enrolled authenticator. No paid messaging service is required.

WebAuthn enrollment and assertion actions are unavailable, and neither customer nor administrator interfaces invoke browser public-key credentials. Historical migration files, public-key records and audit history remain inert. The forward migration clears old challenges and revokes sessions verified using the retired method. Existing authenticator secrets and recovery codes are preserved.

Stripe configuration still requires a verified administrator plus its actual encryption, credential-format, confirmation and provider requirements. Stored credentials, account bindings and prices are unchanged by the authentication migration. Webhook signature checks and duplicate-subscription protection remain enforced. Live checkout still requires separate explicit owner approval, and Cottage Mercantile remains unavailable for live purchase.
